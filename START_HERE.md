# Сначала открой страницу

1. Распакуй архив.
2. Открой папку web-course, затем docs.
3. Дважды нажми на 56-booking.html. Откроется готовая страница, интернет и установка программ не нужны.
4. Проверь выбор месяца, даты, имя, телефон и результат.

Для показа преподавателю нужен опубликованный адрес — сам скачанный HTML не заменяет GitHub Pages.

# Когда будем загружать на GitHub

Исходная игра не удалена: её копия находится в legacy/dice.

## Шаг 1. Открыть загрузку

Открой https://github.com/ImMargaret/web-course.
На вкладке Code нажми Add file → Upload files.

## Шаг 2. Добавить содержимое

Открой распакованную папку web-course на компьютере.
Перетащи в окно GitHub её СОДЕРЖИМОЕ, а не саму папку и не ZIP.
Нужны папки src, docs, scripts, tests, reference, legacy и файлы
package.json, package-lock.json, webpack.config.cjs, index.html, README.md, START_HERE.md, VERIFICATION.md.

Не добавляй node_modules, .git, .openai или qa.
Служебные файлы .gitignore и docs/.nojekyll скрыты Finder; их можно добавить через Create new file,
если они не попали при перетаскивании. Страница будет работать и без .nojekyll, поскольку здесь нет
путей с подчёркиванием, но рекомендуем его сохранить.

Если GitHub сообщает об ограничении количества файлов, загрузку можно разделить на два коммита.
docs должен оказаться в корне репозитория, а index.html — непосредственно внутри docs.

Пример правильного пути: web-course/docs/index.html в адресе GitHub.
Лишняя вложенность web-course/web-course/docs/index.html не нужна.

## Шаг 3. Сохранить

В сообщении коммита напиши Add Project 56 booking prototype.
Нажми Commit changes (или Propose changes, если GitHub предлагает отдельную ветку).
Если создала отдельную ветку, открой pull request и объедини его с основной веткой.

Старый vite.config.js больше не используется; его можно удалить на GitHub после загрузки
нового package.json и webpack.config.cjs. Копия прежней сборки есть в legacy/dice.

## Шаг 4. Включить страницу

В репозитории открой Settings → Pages.
В Build and deployment выбери:

- Source — Deploy from a branch;
- Branch — основная ветка, обычно main;
- Folder — /docs.

Нажми Save. Дождись успешной публикации во вкладке Actions.
Открой адрес, который покажет GitHub в Settings → Pages.
Ожидаемый адрес: https://immargaret.github.io/web-course/ — до публикации он не проверен.

Если по старому адресу ещё открываются кубики, дождись зелёного статуса Pages и обнови страницу
с очисткой кеша: Cmd + Shift + R на Mac.

## Шаг 5. Проверить перед сдачей

Выбери месяц → свободную дату → имя и телефон → подтверждение → результат.
В README уже описаны назначение, работа компонента, стек и использование нейросети.
Проверь ссылку на опубликованный сайт и при необходимости замени её в README.

Важная незакрытая часть требования: точный шаблон Webpack преподавателя не приложен.
Проект уже собирается на Webpack в docs, но перед сдачей нужно сверить его с шаблоном курса,
если преподаватель требует именно свою конфигурацию.
